## Identity / owner decision
Current usage appears single-operator; do not implement multi-tenancy or pretend shared access establishes personal identity. For V2.6 design explicitly enrolled owner credential (e.g. WebAuthn passkey with verified origin/RP ID, challenge, user verification, server-stored public key and recovery enrollment), not a static ID nor a second shared password. Verify actual owner enrollment and workspace association through a protected manual onboarding; bind owner + workspace + account identity + environment + marketplace on server. Never accept client scope. Account switch or revocation increments binding revision and invalidates outstanding approvals; existing blocked descriptors are nonpersistent. Identity API getUser returns account userId, not ELYON user; only attempt read if scope explicitly reported, do not request additional authorization. Hash observed provider userId+environment for diagnostic reference; not owner mapping, not authenticated evidence. A changed observed ID changes reference but no operational approval exists to invalidate. Sandbox identity can be mock; do not use as production proof. Trading GetUser EIAS token is separate identity candidate, not automatic fallback. No account ID fabricated.
