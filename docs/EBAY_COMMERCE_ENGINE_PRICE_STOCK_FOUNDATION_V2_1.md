## Identity / scope
Typed string identifiers: local master ID, canonical product/Company OS ID, ELY article number, explicit eBay SKU, separate supplier SKU/ID/product/variant ID, listingId, offerId, group key, marketplace/currency/environment/account/workspace if provided. Exact SKU and matching saved listing/offer references, not title, URL or supplier code. Duplicate SKU across products or duplicate offers, conflicting stored IDs, mismatched environment/account and conflicting same-SKU listing records are shown as identity conflict. Unknown absence does not mean ended/not-listed. Variant rows come from existing combinations or variants plus explicitly registered channel.variantSkus, including unavailable combinations; a supplier code alone is not an eBay SKU. Unregistered/missing variant identity stays unknown; no fabricated combinations or prefix join. Preserve existing image association in model without loading new external images.
## eBay evidence
Existing authenticated GET /api/ebay/listings and /api/ebay/seller-state retain requireSellerAccess, tokens, lifecycle behavior and all legacy response fields. Add priceStockEvidence (raw availableQuantity, explicit price/currency/marketplace and SKU) and Trading priceStockVariants from existing XML response. No extra API request. Legacy number() coerces missing to zero; new projection never consumes compatibility quantity/price for actual stock/price. Inventory quantity only offer.availableQuantity; inventory-item quantity not necessarily offer quantity. Trading QuantityAvailable only; no fallback to original Quantity or synthetic stock. Trading site must explicitly be Germany and currency explicitly present, otherwise unknown. Trading read path GetMyeBaySelling is not proof of Trading creation origin. Matching Inventory offer confirms Inventory candidate only for display. Feed record is historical processed draft, not verified live draft; no price/stock release. Active Inventory state and Trading live observations kept distinguishable; absent data not classified as ended. Snapshot may be incomplete; no origin inference from absence. No new OAuth scopes or user/account claims. Existing auth scopes access to connected seller session; account identity is not independently verified, no account-bound evidence authorized, no cross-environment or mismatched explicitly claimed account join.
## Supplier and economics
Source fields explicitly separated: stored purchase fact or cost fields, currency, source, timestamp, saved verified status (not authenticated), Amazon retail reference and capture time, supplier-specific quantity and availability, variant combination stock/cost and explicit variantEconomicsFacts if available. No Amazon retail reference as EK, no generic eBay quantity as supplier stock. Zero preserved, missing null, availability only can remain known without quantity. Unavailable variant retained. Saved canonical economics profit, margin, fees, shipping and rule revision only if present; label saved not current and not binding. No calculated profit, no new price proposal. Existing Product Master v2 may omit verified original EK, supplier quantity/time, Amazon reference or revision; legacy projection cannot recover lost provenance, so source remains unverified or missing. No supplier scraping.
