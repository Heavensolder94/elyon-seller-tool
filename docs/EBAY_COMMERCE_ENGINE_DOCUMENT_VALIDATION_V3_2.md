## Technical PDF profile
Bounded strict filename, claimed MIME must be PDF or unknown, canonical Base64 decoding, empty/size/signature/version checks, trailing EOF/startxref, classic xref entries, object positions/end markers, trailer size/root, catalog/pages reference and basic page tree checks. Detect encryption markers including escaped PDF names; reject xref/object streams, hybrid and incremental forms as unsupported, not necessarily invalid. No general PDF parser, no full integrity claim, no malware scan, no rendering, no embedded script execution, no decompression. Conservative profile can reject legitimate PDFs (xref streams, incremental or extra comments); future mature parser/sandbox needed before private delivery. Actual SHA-256 computed server-side over exact bytes. No fabricated file IDs or checksums. Invalid byte check returns typed error and retains previous persisted evidence; current file not considered stored. Evidence revision and monotonically increasing inspection revision, document revision and timestamp. Last three historical inspections retained on replacing/re-saving. No raw bytes or filename-as-path. FileReference/mimeType/fileSize/contentSha256 V3.1 stored-file fields remain null in production; inspected properties in validation.inspection, stored false. Model validation schema elyon-product-document-validation-v3.2 additive, original V3.1 schema preserved.
